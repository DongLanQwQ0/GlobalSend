# GlobalSend 界面规范

本轮重排以清晰任务顺序、可读正文和一致控件为准。保留浅底、白色容器和深绿主色，不增加渐变、装饰插画或新依赖。

## 2026-10-26 第二轮：用户确认后实施

本节覆盖下文与它冲突的旧布局/身份记录约定。默认一切可用，正常状态安静；仅异常、冲突、实际进行中的传输或需要用户决定时显示状态。

- 桌面全局标题右仅放水平的“图标 文本”“图标 剪贴板”。右侧内容区上方放浏览器式“接收 / 已发送 / 文件库”标签；切换只替换右侧内容，左侧待发与草稿保持。移动端导航左“发送”、右“接收”，启动和入组默认发送页；通知明确打开接收时仍进入接收页。
- 待发为单行正方形卡片，区域高度只容纳标题和一行卡片，更多内容在框内横向滚动；空状态保留同样高度。点空白直接打开并聚焦正文输入。缩小设备卡，成功状态短暂显示后复位。释放出的空间增加共享编辑区高度，不缩字号，不让默认934×611客户区左栏整体滚动。
- 共享框不常驻“已同步/编辑中/同步中”。失败/离线仍有未提交内容时提示“未同步”；冲突保留需要作选择的操作。IME、选字和节点稳定不变。
- Win/Android/Web的接收、已发、库与批次卡片统一：菜单右上不挡正文；发送者小号淡色左下，复制右下；整卡点击承担原查看/编辑，不再另放“查看”。多选时整卡只选择。正文按完整行截断，文件名扩展名不孤行。今天和昨天仅HH:mm，更早MM/DD HH:mm；无“接收”时间前缀。
- 实际文字上选择；文字外的行尾、段间、下方空白可拖整段。共享也支持文本拖放。窗口内从接收/已发/库拖到待发用于下轮发送，明确落区反馈；外部全窗拖入继续可用。拖动有真实内容跟手预览与系统复制反馈。
- Windows Esc逐层关闭菜单/弹层/预览并回上页，不直接退出；IME先取消组字，未保存草稿保留。图片/文件预览双击系统默认应用打开，缩放另走滚轮/手势/控件。
- Windows后台接收使用独立右下角接收坞：无标题、透明圆角外沿抗锯齿、有进退动画、不抢焦点；主窗口有焦点时在主窗口内接收。不得再调整主窗口位置/尺寸来冒充接收坞。后台网络/session仍只一份，接收坞仅呈现内容，关闭不删历史/不中止传输。
- Android展示策略：不新增无障碍权限。不再缩小主Activity或绘制假窗口外框；用户通过vivo系统手势进入自由窗时，边框、圆角和缩放交给系统。后台自动接收使用独立紧凑悬浮窗后备（已有悬浮窗权限），窗口外可直接操作其它应用；无权限或展示失败才发通知。显式打开恢复普通主界面，不承诺未公开的vivo自动自由窗接口。
- Windows接收坞固定约480×184逻辑像素，横向滚动正方形卡，不因批量接收加高；首次从右侧进入，关闭退出。已存在时只对新卡做落入/旧卡右移，进度更新不重播入场。背景透明、控件半透明；标题空白可移动，Alt拖动可从任意区域移动。内容拖动仍用于导出，正文可选字。
- 已发送与接收均支持多选、全选、批量删除；切换标签清空选集，删除已发只移除记录/引用，不删除外部原件。空剪贴板操作静默返回。
- 组内共享提供连续撤销/重做及标准快捷键；本地和同步收到的正文修改进入同一文档时间线，自身确认不清历史、不添加假步骤。撤销后的内容正常同步，IME整次提交；切换不同组/文档才换时间线。
- 点击GlobalSend标题列出本机IP，排除IPv4 127/8、IPv6 ::1及mapped环回；Native外层按网卡名称/系统来源分组，内部按IPv4内网、IPv4公网、IPv6内网、IPv6公网数值排序，保留跨网卡重复和IPv6 scope。特殊保留地址明确标注，不冒充公网。显示系统给出的Wi-Fi、蜂窝、IMS、VPN类型和网卡描述；程序归属不可得时不猜测。Web仅按浏览器本机、公开映射及已发布地址来源分组，浏览器没有提供网卡/程序归属时不伪造。点选纯IP加入待发，不列其它设备或mDNS主机名。
- Windows原生外拖返回应用时继续显示系统拖影，只在待发区域接受本应用回投；结束后可再拖。接收坞本身不接收文件，但维护系统拖影和禁止落下提示。文本原生拖影为紧凑圆角摘要，保留复制语义。
- Android原生拖放可回投可见待发区，外部拖入仍整窗；从接收页拖动可在“发送”导航项悬停350ms切页，再投放队列。拖动期间保留源ViewRoot并延迟新的接收弹层，结束恢复；正常取消不弹原始异常。
- Windows命令行接受多个文件/文件夹路径；已有进程转交并唤起既有窗口，内容仅加入待发。支持资源管理器“发送到GlobalSend”。
- 同一份客户端本地数据代表连续的本地用户：切组/访问密钥/恢复登录不隔离旧文件与已发/接收历史；移除“旧身份记录”入口，把旧内容合入普通历史。服务器/组的远程授权仍各归其会话，不能把旧transferId/token用于新组；旧文件通过本地引用再发送，不额外复制。
- 文件库和历史自动检查真实本地引用，移除已不存在内容；删除发送引用不得删外部原件。传输中显示真实字节/秒。先核对各路断点恢复已有机制，再评估有收益的并行分块，不能为“多线程”引入整份重传或浪费中继流量。

当前实施所有者：Native UI负责页面与交互；Windows原生负责独立接收坞/启动参数/原生拖影；Web负责对应工作流；root负责连续历史、速度/恢复、主入口接线和最终整合。真机、实体触屏和系统窗口合成结果仍需对应实际证据。

## 共同尺寸与视觉语言

- 间距只用 **8 / 12 / 16 / 24 / 32** 为主。字段之间 16–20，独立分区 24；紧凑工作区节奏 12，不能靠缩小文字塞满。
- 页面底 `#F4F6F2`，容器白，输入底 `#FAFCF9`；正文 `#202923`，次要文字 `#667068`，细边 `#DFE6DF`，主色 `#176B50`。绿色用于主操作、状态或选中，不让所有对话框蒙绿。
- 普通容器圆角 20、字段/按钮 14、紧凑内容卡 16。边框表达分组，不给每一行都画线。
- 正文 16、行高约 1.55；辅助信息通常 13–14。标题 24，分区标题 16、半粗。保持既有字体及系统中文回退，不下载大型字体影响 APK 体积。
- 主要/次要按钮高 48，工具按钮至少 40，图标点击范围至少 40；一个区域只有一个主操作。主次按钮同高同圆角，按钮之间 12。

## 字段、下拉与展开属于同一套组件

- 单行输入和下拉约 56 高，内边距横向 16、纵向约 16。标签放在框外上方，间距 8，聚焦和有值时都能读到。
- 文字不能贴边，标签不能被框线切开或被上一个字段挤压。错误信息占字段下方空间，不覆盖边框或下一个字段。
- 不用额外的局部 dense/padding 覆盖破坏统一控件。下拉值、箭头与输入文字对齐，弹出选项同样有留白。
- 少量基本字段直接展示，不增加“更多/高级”展开。真正需要收起的内容用统一圆角分区、完整点击标题、内边距和明确箭头；去掉默认上下横线。
- 聚焦节点、输入 controller、选区和 IME 组字状态保持。键盘改变高度时不能换父树导致失焦。

## 页面层级

- **连接/恢复**：Native 桌面约 600–640 宽的完整卡片，形成接近方形的整体；服务器独立行，设备名/组密码可并列，手机单列。恢复状态有独立轻提示区；重试为主、重新入组为次，同排且留距。诊断和服务器设置为明确次级入口，不把所有内容压在竖向展开里。Web 自动使用网页来源中心，普通入组不增加手填服务器步骤；其较少字段可使用 480–520 宽卡片，不强行复制 Native 的字段数量。
- **正文编辑/查看**：独立内容区域接近 **4:3**，约 20 内边距，支持滚动和缩放视口；不是一条狭长输入线。收到只读、已发可编辑、复制一个入口。单行密码和地址仍是单行控件，不做方框。
- **工作区**：内容 → 目标 → 组内共享。Windows 默认 950×650 外窗（约 **934×611 客户区**）左侧整体不滚动，队列和目标各自滚动。共享框使用当前高度预算，不能为做成方形挤掉其它必需区域。大窗口自然增加留白。
- **接收/已发送/文件库**：两列内容卡，统一预览、名称、大小/时间和动作的层级。正文/文件信息内边距至少 16；长名称换行或省略，不把字体缩到难读。主接收列表和批次弹层统一两列。
- **选择态**：所有类型选择标志统一左上；只显示选择、内容和基本信息，不保留看似可点的普通动作。整卡语义为选择，退出恢复普通查看/复制/拖出。
- **设置**：少数清晰白色分区，分区间 24，行间 16。名称、下拉、开关对齐；结果由当前值体现，不堆重复解释。HTTP 等既有条件保持，入口清楚但不占 HTTPS 默认主路径。
- **用词**：统一“设备名称”“组密码”“切换分组”“接收位置”。网络路由用“发送方式/接收方式”，不要也叫“接收路径”而和文件保存目录混淆；正文元信息为“n 字符”，文件为 B/KiB/MiB。
- **菜单/弹层/状态**：统一圆角、标题间距、按钮与关闭范围。明确检查空、加载、错误、长文本、长文件名、无设备及设备很多时的状态。

## 不能牺牲的原行为

静默共享与手机键盘、单击设备发送和显式多目标确认、全窗口拖入、正文选字/文件整卡拖出、多选全选批删、系统媒体 Picker、收件 ACK/arrival 代次、托盘草稿、凭据默认原身份重试与确认恢复、旧记录只读和文件库保留均不变。

## 完成判断

查看最终实际渲染，不只看组件返回或编译。Native 检查 934×611、390×844 和 1.3 字号；Web 检查 950×650、390×844 和相应字体放大。正文与弹层包含真实长内容，字段与下拉包含已填值/聚焦/展开/错误状态。交互只跑受改变的关键路径；浏览器始终复用既有持久 profile。所有截图先压缩副本再查看。

不在旧规则上不断追加覆盖层：统一当前实际使用的规则/组件，并检查相邻页面。未取得的手机/实体触屏/系统合成器结果单独保留，不把渲染检查写成硬件通过。
