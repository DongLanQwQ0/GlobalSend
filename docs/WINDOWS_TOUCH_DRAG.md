# Windows 触屏拖放

1.0.84+109 继续修正启动等待、拖影刚出现就结束及消失后重新出现的问题。108的基本触屏拖动已获用户确认；这次保留同一原生跨应用路径，修正准备与交接顺序。

- 转换触点的请求返回成功，不代表系统鼠标按下事件已经交付。109等待真实兼容鼠标流后才进入OLE，避免第一次按键查询为零便结束。
- 窗内Flutter拖影保留到匹配的 `dragSessionId` 原生开始通知；退休后，结束回调、重复或晚到通知不会再把它恢复。主窗口与接收坞分别使用自己的消息通道。
- 已有RGBA像素直接生成拖影位图，不再复制到闭包、开线程、初始化COM并等待准备消息。没有现成预览的既有调用仍使用异步准备。
- 保留500 ms长按识别及必要的首帧绘制/像素读回；本轮减少额外准备等待，不把局部位图计时冒称完整触屏延迟。

移动、抬手和跨应用投放继续由系统 OLE 处理，复用窗口内外的同一拖影和数据对象。旧的逐事件 `SendInput` 与低级鼠标钩子分支已移除。准备期间松手、取消或触点被替换会结束该次准备，不消耗下一次触点；转换失败会保留实际 Windows 错误码。

## 当前证据

- 相同隐藏窗口输入顺序下，108复现过早进入OLE、首次按键查询导致取消；109不在真实按下前调用OLE，复制成功且只启动一次。
- 隐藏 HWND 检查覆盖真实消息上下文、系统兼容流、准备期间抬手、1000次移动、捕获交接、drop/cancel、触点编号复用和主窗口/接收坞隔离；22项Flutter聚焦检查通过，最终平台保护修改后的7项复查也通过。
- 生产触屏、系统桥、接收坞及相邻可视夹具 MSVC `/W4 /WX` 编译通过；既有文件/目录准备及取消组件检查通过。测试卡片和坞的压缩渲染已查看。
- 证据：`artifacts/tmp/windows-touch-handoff-20261102/RESULT.md`。原始108修复记录仍保留在 `artifacts/tmp/windows-touch-native-20261102/RESULT.md`。
- 按用户要求，没有操作实际 Windows 桌面、剪贴板或触屏。实际触屏跨应用投放及拖影连续性仍待用户验收；组件里的系统转换和 OLE 回调替身不能代替它。

截图当次旧版本没有保存 `GetLastError`，无法追溯那一次系统拒绝的确切原因。当前修复针对可从源码证明的异步接管和重复转换问题。

## 系统接口

[ConvertPrimaryPointerToMouseDrag](https://learn.microsoft.com/en-us/windows/win32/winmsg/winuser/nf-winuser-convertprimarypointertomousedrag) 将正在进行的主触点转换为系统鼠标消息流；[DoDragDrop](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-dodragdrop) 负责目标检测与 OLE 投放。应用不再自行逐次注入移动和松手。
