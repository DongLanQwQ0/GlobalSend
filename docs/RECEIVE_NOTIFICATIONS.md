# Android 接收展示与通知

本页按当前源码说明机制；运行版本与候选的区别见 [快速测试](QUICK_TEST.md)。

## 当前用的是什么小窗

后台收件使用 `ReceiveOverlay`：一个独立的系统 overlay，默认约 **272×184 dp**，不缩放 MainActivity，也不铺全屏遮罩。顶部可移动，底部手柄可缩放；卡片横向排列，长按沿系统拖放导出。窗口外仍能操作其他应用。打开箭头或卡片进入正常应用，关闭只收起展示，不删除接收历史。

这不是 vivo 原生自由窗口。源码只查询系统是否报告 freeform 能力，**没有自动调起 OEM 原生小窗的路径**；旧 Activity 缩放适配已退役。原生小窗优先仍受 OEM 可用接口限制，不能用当前 overlay 冒充。当前不新增无障碍权限、不读取其他 App 窗口、不自动判断桌面，保留手动打开全屏。

## 先展示，失败才通知

- 前台在应用内显示接收内容；组内共享始终静默，不生成收件、通知或唤起。
- 后台弹出默认开启，overlay 需要用户授予“显示在其他应用上层”权限。授权和后台接收设置互相独立。
- 有实际内容的首帧确认显示后，抑制这次聊天通知。未能展示、未授权或关闭后台弹出时，改用通知；展示确认约一秒内完成。
- 每条内容独立处理动作；新版本重新提醒，同条修改替换对应通知，重复回放不重复提醒。通知“复制”取得该条最新全文，点击打开对应内容。
- Android 13+ 的通知授权、通知通道重要性会影响后备通知和悬浮横幅。后台接收服务的低重要性常驻通知单独保留，不属于聊天提醒。

后台监听由同一接收引擎和前台服务维持，文件传输期间持有唤醒锁，空闲不持有。可在设置开启后台接收，并按需要允许本应用后台运行；系统强行停止后需手动重新打开。

## 手机上这样验收

1. 应用前台收文字、图片、连续多项：不重复通知；候选的接收页/弹层按最新接收在前。只读正文拖动不选字，复制按钮仍可用。
2. 切到其他应用再接收：小窗只占自身范围，背景能点击；移动、缩放、长按拖出，再拖回发送区。关闭后继续收新内容，应再次正常显示。
3. 未授权或关闭后台弹出时收文字：检查通知和“复制”。保留旧通知再发新消息、修改原消息，仍应提醒且复制最新内容。
4. 成功弹出后立即关闭：不应再补同条通知。点击打开后检查历史保留；共享编辑不触发以上任何提醒。
5. 熄屏等待小文件接收，再亮屏查看完成状态。记录 vivo 的实际后台稳定性，不以组件测试代替真机结果。

## 尚待整合验收

当前 overlay 源码有约 180 ms 的进入动画，关闭为立即移除，**尚无退出动画**；卡片也不是 Windows 接收坞的透明控件实现。不要把 Windows 的全透明背景/半透明控件和进退动画报告套用到 Android。真实跨应用触摸、拖放和多轮后台结果需更新后的手机版本确认。

实现入口：`ReceiveOverlay.java`、`ReceiveNotifications.java`、`ReceiveNotificationBridge.java`、`BackgroundReceiveService.java`。候选拖放证据见 [正文整体拖动](../artifacts/reports/receipt-text-drag-region-1.0.19.md)，发布前检查见 [UI 验收](UI_ACCEPTANCE.md)。
