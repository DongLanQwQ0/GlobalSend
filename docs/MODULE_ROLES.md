# 模块定位与界面交接

本文明确 GlobalSend 各模块的职责，用于后续 UI 优化。功能基线为 **1.0.89+114**；具体入口重排是评审方案，尚未替换运行客户端。组件与内容状态的名称沿用 [组件命名](COMPONENTS.md)。

## 三个模块不是三个大小不同的主页

| 模块 | 定位 | 首要任务 | 使用环境 |
| --- | --- | --- | --- |
| 主界面 | 完整工作台 | 准备内容、选目标、收发与管理 | 用户主动打开应用 |
| Android 悬浮暂存坞 | 跨应用中转站 | 接住、暂存、拖出或投给设备 | 用户正在其它应用中 |
| Windows 接收窗口 | 后台到件入口 | 即时看到进度、预览、取走内容 | 主窗口没有焦点，用户正在桌面工作 |

三者共享内容身份、传输状态和设备数据，不各自生成第二份历史、独立下载或另一套同步配置。

## 主界面：完整工作台

### 承担的功能

- 待发送区：添加文字、剪贴板、文件、文件夹、媒体，以及查看本批内容。
- 设备区：点设备发送、直接拖入设备发送、本次多设备发送、刷新和可达性详情。
- 组内共享区：持续共同编辑、撤销/重做；文件复制引用独立排布，不能混入正文。
- 自动剪贴板槽位：固定展示最新内容，保持独立身份，不冒充普通收件。
- 接收、已发送、文件库：完整查找、筛选、排序、预览、转发和批量整理。
- 全局配置：连接与分组、接收位置、清理、后台、主题、更新与使用指南。

### 空间与交互

主界面拥有最多的工作空间，应承担持续编辑和完整管理。Windows保留发送/整理左右两窗格；待发送按一行方形卡片安排，设备保持紧凑，为共享编辑让出高度。手机保留发送、接收、历史、文件四项导航。iPad根据实际窗口宽度适配，而不是仅根据设备名称强制桌面布局。

高频添加动作和设备目标应直接可见。设置只管理持续偏好，不承担“每次发送”的必经步骤。设备旁的定向自动化快捷入口若实施，必须指向同一份配置，不能再创建一份开关或目标状态。

### 生命周期与交接

- 切页、切组、失焦或关闭主窗，不得混淆草稿、历史和本地文件的身份。
- Windows有焦点时在主界面接收；失焦时由独立接收窗口呈现，不缩小或移动主窗冒充接收坞。
- Android跨应用临时中转交给悬浮暂存坞；完整管理仍回主界面。

## Android 悬浮暂存坞：跨应用中转站

### 承担的功能

- **接收视图**：取用别人送来的正式内容；有自动剪贴板槽位时固定第一位。
- **暂存视图**：放下自己从其它应用拖入的内容，稍后继续拖出或发送。
- **建议与引用**：建议未确认不混入正式暂存；未拉取引用不冒充本地文件。
- **快捷投递**：拖出内容后显示设备；外部内容悬停2秒进入设备模式；边缘停留连续滚动。
- **就地操作**：单项移出、批量移出、单项/全部拖放、文本复制和可识别链接打开。
- **空间控制**：贴物理边缘收起、展开、移动、边缘缩放，保留位置和横竖屏适配。

### 空间与交互

背景应用应继续可用。坞保持小、薄、半透明；内容卡片是视觉主体，图片铺满卡片，文本使用卡片内空间。接收、暂存、拖动控件靠展开侧边竖排，不占一整条顶部工具栏。交互控件之外可跟手移动；卡片拖放、列表滑动、移动和缩放的命中必须区分。

普通内容和清空卡之后保留一格空白，用于双击打开主应用；建议紧接这格空白，不以整屏占位把建议推出视野。它不承载完整历史、网络诊断或长篇设置。

### 生命周期与交接

- 暂存是本机引用；成功投放后标红，3秒后移出。点坞或再次开始拖动可取消这一批移出，不删除来源原件。
- 媒体建议累计30秒真实可见闲置时间；未滑到、收起、操作中不计时。确认进入暂存后改用暂存规则；建议直接拖放成功则消耗建议。
- 普通新收件可展开坞；自动剪贴板更新不新弹、不展开，不写普通收件/历史。
- 双击末尾空白格回主界面。完整检索、编辑、批量文件管理、路径诊断和偏好调整交回主界面。
- 悬浮坞不是厂商原生自由窗，也不应用全屏透明Activity遮挡其它应用。

## Windows 接收窗口：后台到件入口

### 承担的功能

- 普通收件开始时立即出现，展示真实进度，而不是等文件完成后才启动界面。
- 图片与文本直接预览；卡片省去不必要的底部元数据，最新收到的在前。
- 内容原生拖出、点击链接、快捷菜单和必要的单项处理。
- 已显示时静默刷新自动剪贴板槽位；槽位更新自身不能触发窗口出现。
- 外部内容悬停2秒后切换为设备目标，允许顺手继续投递。

### 空间与交互

采用紧凑、无标题的半透明横向窗格，多项内容横向滚动。新增一批不能把它撑成一整页，也不能重复创建覆盖窗口。首次出现/关闭与已显示时新增卡片使用不同动画，不在每次更新时重新滑入整个窗口。

空白处单击打开主窗口；拖动空白移动窗口并保留抓取点，不能先将左上角吸到光标。内容区域拖动导出真实内容；菜单和按钮保留各自行为。后台接收不抢焦点、不改变主窗位置和大小。

### 生命周期与交接

- 接收窗口只是已有收件与任务的视图，不拥有第二套持久历史。
- 关闭接收窗口不删除已保存文件，不中断接收核心或传输。
- 完整编辑、历史检索、分类整理、批量文件管理与设置回主界面。
- 它不等同于Android可长期放内容的悬浮暂存坞，不能因为两个模块都叫“坞”而复制所有功能。

## 四种内容状态，在所有模块中保持一致

| 内容 | 是否已在本机 | 主操作 | 是否进入普通发送/历史 |
| --- | --- | --- | --- |
| 建议卡片 | 内容可从剪贴板或媒体来源取得，但尚未确认 | 点按确认或直接拖动 | 不随普通发送；确认后才成为正式内容 |
| 文件复制引用卡 | 未拉取时原件仍在来源设备 | 拉取；原生可按需拖放 | 手动拉取不弹收件强调页；已有副本不重复下载 |
| 本地副本/正式内容 | 已有可读的本地内容 | 预览、拖动、发送或管理 | 按正常收发规则处理 |
| 自动剪贴板槽位 | 最新同步内容 | 支持的平台写剪贴板；拖动或主动加入待发送/暂存 | 全局只有一份，不写普通收件、历史和文件库 |

组内共享文本另有定位：它是共同编辑的文档，不是待发送消息，也不是自动剪贴板槽位。同步不唤起、不弹收件页，正常时无需重复显示“已同步”。

## 平台专属边界

- **Windows**：托盘保持接收核心，主窗与接收窗分工；鼠标/触屏沿用原生拖放。
- **Android**：悬浮暂存坞承担应用外中转，后台受系统调度；通知是弹出不可用时的后备入口。
- **iOS**：以系统分享和前台收发为主；不能套用Android悬浮坞、远程自动唤起的承诺。
- **iPadOS**：利用分屏/台前调度和原生跨应用拖放；主界面与返回按钮避让系统窗口控制。与iPhone共用IPA，但分别验收。
- **Web**：工作区语义与原生保持一致；文件存储、剪贴板、系统通知和后台受浏览器能力约束。没有退出浏览器后的服务端Web Push，也没有原生的延迟文件提供方。

## 后续 UI 评审顺序

1. 确认上述模块职责和四种内容状态，再讨论尺寸、颜色与按钮。
2. 优先拆清建议、自动同步、文件复制引用；把定向配置靠近设备，仍复用原配置。
3. 主界面优化信息层级；Android坞优化中转效率；Windows接收窗口优化即时取用。
4. 平台专有入口只出现在相关场景，正常状态安静，异常或需要决定时再解释。
5. 核对 [待验收项](REQUIREMENTS_STATUS.md)，不能把评审示意图当作真实系统交互已通过。
