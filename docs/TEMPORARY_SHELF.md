# Android 文件暂存坞

- 设置 → 接收与暂存坞：用开关打开、关闭独立悬浮窗。没有悬浮窗权限时提供授权入口，恢复并确认授权后再显示。
- “接收”和“暂存”独立；外部拖入只进入暂存，不生成接收记录或待发送任务。
- 操作栏可拖动窗口；轻点按钮保留原功能，长按六点图标仍拖出全部内容。
- 操作栏使用“数量 + 收件箱 / 文件夹图标”切换接收和暂存，数量紧贴对应图标；完整含义保留在无障碍说明中。
- 操作栏随贴边方向镜像：右侧贴边时在右，左侧贴边时在左，内容向屏幕内展开，外侧只留1dp。默认232×116dp，可缩小至152×92dp，卡片间距3dp。没有额外的调整图标，直接拖四边或四角改变尺寸。背景和内边距可按住移动，保留按下点偏移；按钮、卡片系统拖放和内容横向滚动各自响应。
- 展开时边缘缩放热区为内侧12dp，四角为20dp；可见边框不加粗，不扩大窗口遮挡范围。删除、复制和操作栏按钮优先于缩放。横向滚动内容延伸至窗格外沿，由整体圆角收边；不再生成外部悬浮阴影层。
- 接收使用绿色，暂存跟随主题色；绿色主题下，接收改用偏黄的绿色，与暂存的冷绿色区分。卡片不重复显示“接收／暂存”分类文字，图片铺满整张卡片，保持比例居中裁剪并沿卡片圆角收边；移除按钮叠在右上角。
- 将窗格拖到边缘，收为视觉 12 × 48 dp 的细把手；透明触控范围为 18 × 72 dp（1.5倍），不放大可见元素。点击或向内拉展开；把手可沿边缘上下移动。内容与窗格同步滑动、收拢，展开反向进行，不压缩卡片排版。
- 收起把手上下拖动松手后，按手指的屏幕移动速度惯性减速，保持所在侧边并限制在屏幕安全区域；再次按住立即停止，最终位置继续记忆。轻点展开和向内拉出不触发惯性。
- 悬浮窗展开时使用系统长按级触感，比轻触反馈更明确；拖动内容刚进入悬浮窗范围时同样反馈一次，移出后重入可再次反馈，范围内移动或完成投放不重复震动。遵循系统触感开关，不增加振动权限。
- 操作栏只保留两类数量图标和全部拖出，不放关闭、收起或打开按钮。双击中间内容区打开主应用；复制、移除等按钮不触发双击打开，长按仍走系统拖放。
- 暂存横向顺序为：已有内容 → 清空 → 一整格透明空白 → 建议区。图片、视频和剪贴板建议在同一区域按建议时间倒序排列，不再固定把剪贴板追加在最后。没有已有内容时，先保留一屏空白，向左滑才露出建议。空白始终支持双击打开GlobalSend，不计入数量、不参与全部拖出；接收列表不混入建议。
- Android使用已有“新图片与视频建议”开关，不再重复弹出主页面的图片提示。每个媒体只建议一次，未确认图片／视频建议与主应用一样在8秒后自动清除引用，不删除原件；已明确加入暂存的内容保留。剪贴板建议仍需点击添加或手动忽略，不随媒体的8秒期限清除。建议不参与“全部拖出”，明确暂存后沿用成功后3秒移除与轻点取消。新建议不会抢先展开窗口或切换标签。
- 媒体库变化、窗口恢复以及每5秒后台检查已列出的建议。原件已删除、进入回收站，或已在主应用忽略时，移除对应建议引用；即使文件管理器未通知MediaStore也会检查。重启不重新计时或显示已到期的建议；不影响手动暂存、接收记录或媒体原件。
- 从坞中长按单项或全部拖出，离开坞后临时切换为横向设备栏；悬停两侧边缘自动滚动，设备卡片高亮表示当前投放目标。松手只发送本次拖出的内容，不发送或清空主页面草稿。拖动结束恢复原列表与滚动位置；仍可拖至其他应用。设备使用同中心唯一ID，发送失败保留内容；暂存发送请求成功后沿用3秒移除引用与轻点取消，接收记录不删除。
- 设备栏边缘滚动跟随屏幕VSync，按实际帧间隔计算距离并保留小数位；越靠近边缘越快，进入和左右反向时平滑变速，离开边缘立即停止，不再以固定16ms定时器逐格跳动。
- 展开使用半透明窗格和卡片；收起后仅保留更淡的把手，可见区域外的增大触控区完全透明。
- 左右两侧使用同一段镜像动画，同时移动、收拢或展开。动画期间只在两端位置的并集内保留临时OS窗口，实际窗格在同一绘制时钟上变化，不逐帧请求系统移动/缩放；结束立即收紧触控范围。
- Android14及以上关闭系统附加的窗口位移动画，避免右侧收拢结束后再次从旧窗口原点滑入。新收件自动展开；卡片单独滑入淡入、删除淡出，已有卡片平移让位，不重播整窗出现动画。
- 横竖屏切换后保留贴边方向、收起/展开状态和相对位置，按新屏幕安全区域重新定位；尺寸临时受限后，空间恢复时还原手动调整的尺寸。旋转不重建坞或清空暂存。
- 拖动内容悬停把手 250 ms 后展开；支持多批追加、多文件与文本混合投放。复制文件在后台完成，导入时显示等待状态。
- 长按卡片拖出单项；长按六点图标拖出当前标签的全部内容。沿用 Android 系统拖放。
- 暂存项在系统报告接收后开始3秒倒计时，标红并显示删除图标；普通文件在到期时还要确认目标打开读取描述符或取得兼容文件路径，未获取则保留并提示。源应用及系统拖影预览不算目标获取；文本与目录沿用系统投放结果。坞隐藏后倒计时仍生效；轻点坞内任意位置或再次拖动任意项，取消整批待移除。取消用的轻点不穿透成打开文件，长按仍可继续系统拖放。失败、取消、回投暂存坞都保留。
- 自动移除只清除暂存引用，不删除原件，也不改接收记录。外部 URI 的暂存副本位于应用缓存；元数据独立保存于 `temporary-shelf.json`。
- 普通文本暂存项点击复制；文件项点击系统打开。复制成功显示“已复制”。每项右上角 × 直接移除，透明背景、36dp触控区域；末尾同尺寸的 × 卡片清空当前标签。不经二次菜单，不删除文件原件或主页面的接收记录。
- 主应用回到前台时收起坞，不销毁暂存内容。仅从设置关闭；关闭后保留暂存内容，后续收件走通知，不自动再次打开坞。
- 开关保持打开且悬浮窗权限可用时，后台运行时恢复或重新进入应用会自动重建，不必等待下一次收件；主应用在前台时显示贴边把手，开关关闭不重建。系统“强行停止”应用会阻止后台自启，需先重新打开应用。
- 记住最后位置、贴边方向与手动尺寸；横竖屏各保留自己的位置。恢复时先设置位置再创建OS窗口；后台恢复保留上次展开/收起状态，主应用已在前台则恢复为把手，不闪出展开窗格。换方向时保留当前贴边方向，位置适配安全区域。
- 原生拖影、坞与主界面使用同一外观配置。跟随系统时，系统明暗变化会更新配色。

## 验收重点

1. 后台分别拖入图片、视频、PDF 和文字；连续两批不覆盖，接收记录不增加。
2. 贴左/右边收起、上下移动、向内拉出；按钮栏始终位于相应贴边侧，切换分类、重启和旋转后保持一致；坞外区域仍可操作其它应用。
3. 单项和全部拖出到其它应用；成功 3 秒后移除，轻点取消；取消拖动和回投不移除。
4. 不同主题下检查原生拖影，图片本身不被主题染色。
5. 冷后台时的第三方 URI 读取仍需真机验收：[Android 公开接口](https://developer.android.com/reference/android/app/Activity#requestDragAndDropPermissions(android.view.DragEvent))将拖放读取授权绑定到 Activity；当前复用仍存活的宿主 Activity，不增加隐藏权限接口或无障碍服务。

已验证：Android 框架混合投放与后台复制、原生完成结果、分区、窗口实际缩放、3 秒移除及取消逻辑；Flutter 主题/应用选择与桌面拖影锚点。真机跨应用拖放不以框架测试代替。

历史40版中，同一提前打开的微信聊天只能插入相册来源，不能插入GlobalSend来源；当时系统投放回执不足以证明插入。1.0.40加入按需启用的`GlobalSendDrag`诊断，只记录请求类型、调用UID和打开结果，不记录URI或正文。

1.0.41已将普通文件的本地路径和SAF URI统一导出为带真实文件名的只读URI。文档通过已授权的描述符、asset及typed stream转发，保留偏移与长度，不复制文件字节；目录仍保留原有文档URI，避免破坏目录语义。框架检查覆盖真实描述符读取、元数据、外部读取标记与未读取时保留；微信插入仍未通过，不以系统回执或独立测试接收器代替。

真机41日志已定位一个误判：`com.vivo.globaldragdrop`在投放前为拖影预览打开文件，微信只查询元数据而未打开。42明确排除此系统预览进程，不将其计为目标读取；这是读取回执修正，不代表微信直接插入已完成。用户提供的“该页面位置不支持插入”分享面板截图记录于项目验收资料。

1.0.48将操作栏、内容区外沿留白一起按贴边方向镜像；恢复左侧位置时，在创建窗口前排好按钮。框架检查通过后，USB真机完成三次左右贴边往返及横屏/竖屏恢复。合成图片经生产暂存坞投放至路径型接收器实际可读，再投至微信文件传输助手，微信实际显示图片；暂存随后归零。用户确认窗口、投放和重启位置记忆正常，要求停止这部分后续测试。记录：`artifacts/screenshots/phone48-usb-resumed/acceptance.json`，微信过程见[兼容记录](WECHAT_DRAG_COMPAT.md)。
