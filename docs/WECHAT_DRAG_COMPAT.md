# Android 文件拖入微信的路径兼容

## 已定位的接口不匹配

同台手机的微信为8.0.79（3200）。只读检查已安装APK的聊天拖放处理发现：它申请拖放授权后，查询URI的默认列，并从`_data`读取真实文件路径；没有这一列就中止文件处理。它不是只依靠`openInputStream`读取文件。

GlobalSend原接口只提供名称、大小及读取描述符。因此，标准接收器能够读取，不代表微信的路径型接收器能读取。43仅补图片标记的尝试未解决，44移除该无效尝试。

真实手机的43对照结果：接收器已取得URI授权，但按路径读取失败，记录于`artifacts/reports/phone-43-legacy-path-baseline.json`。相册、超级截图和其它应用可用是用户实测；不把差异归结为相册专属格式。

## 44的处理

- 默认元数据增加`_data`。已有公共文件路径直接复用；常规名称、大小查询和内容流读取保持原合同。
- 微信的默认查询，或其它接收器明确查询`_data`时，才准备私有文件的兼容路径。自己绘制预览、vivo拖影服务和普通名称/大小查询不触发复制。
- Android10及以上的私有文件必要时写入应用自行创建的MediaStore临时记录，位于`Download/GlobalSend/Drag-cache`。向实际接收方授予该记录的只读权限，不请求新的全盘权限。
- 字节复制在外部Provider请求线程完成，不在GlobalSend主线程。相同拖放URI的重复查询复用同一副本。
- 临时副本保留10分钟，按本应用记录的精确MediaStore URI清理；进程重启后恢复清理。原件、接收目录和其它应用的记录不随之删除。
- 暂存引用的3秒移除同时依据系统投放结果及目标的描述符读取/兼容路径获取；系统拖影预览不算目标获取。

这是对发送端提供的数据接口做兼容，不修改微信、不使用无障碍，也不代替用户发送聊天消息。文本与目录的既有拖放语义保持不变。

## 验证状态

框架检查已覆盖私有文件的路径准备、公共原件/MediaStore原件复用、重复查询复用、失败后清理、文档asset偏移、原件保留及原有多文件拖放。44仍需在同台手机检查真实路径读取，再由用户确认正常微信聊天窗口的图片插入；不能用构建成功代替这一步。
