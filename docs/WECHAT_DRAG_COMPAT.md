# Android 文件拖入微信的路径兼容

## 已确认的接口差异

同台手机安装的微信为 8.0.79（3200）。只读检查其聊天拖放处理发现：申请拖放授权后，它查询 URI 的默认列，从 `_data` 取真实文件路径；该分支没有内容流回退。GlobalSend 只提供读取描述符时，标准接收器可读，微信的路径型处理仍会失败。

用户实测：正常、无遮挡、提前打开的微信聊天，在 43 上松手后没有图片或附件；相册、超级截图等来源可插入。43 仅补图片标记没有改善，44 已撤掉这一无效配置。系统分享面板或拖放返回成功都不代表聊天已插入。

## 路径和授权一起提供

- 默认元数据包括名称、大小及 `_data`。只有目标要求真实路径时才准备兼容数据；自己的预览、vivo 拖影服务及普通名称/大小查询不复制。
- 46 修复私有文件兼容副本的授权：Android 的路径访问检查使用 Images/Video/Audio/Files 的对应 URI，不是插入时的 Downloads URI。因此实际目标同时得到同一行的精确只读授权。
- 47 补齐公共目录与 MediaStore 原件：已有媒体行直接复用原路径，同时授予该行及对应类型 URI 的读取权限，不复制原件。没有可复用媒体行、或仅有私有/虚拟内容流时，才创建短期兼容副本。
- 私有兼容副本位于 `Download/GlobalSend/Drag-cache`。字节复制在外部 Provider 请求线程完成，重复查询复用同一副本。10 分钟后只清理本应用精确记录的副本，重启后恢复。
- 原件的短期读授权单独记录、到期撤销，永远不删除其媒体行或原文件。普通内容流、asset 偏移和目录的既有接口保留。
- 暂存引用的 3 秒移除仍依据系统投放结果和目标的描述符读取/兼容路径获取；系统拖影预览不算目标获取。该回执不能证明第三方 UI 已完成插入。

## 实际证据

复用原有 Android 36 模拟器，在不同 UID 的独立接收器中测试生产 Provider，目标没有 READ_MEDIA_IMAGES：

| 来源 | 修复前 | 修复后 |
| --- | --- | --- |
| 私有 PNG / 普通文件 | 路径读取 EACCES | 46 同行 typed URI 授权后可读 |
| 已有公共目录图片 | 46 路径存在但读取 EACCES | 47 可读，复用原媒体行 |
| MediaStore Downloads 图片 | 46 路径存在但读取 EACCES | 47 可读，复用原媒体行 |

`artifacts/reports/emulator46-public-path-baseline.json`、`emulator46-media-path-baseline.json` 与 `emulator47-publicSource-path.json`、`emulator47-mediaSource-path.json` 记录了源/目标 UID、实际权限和读取结果，不记录正文或路径。

框架检查覆盖私有文件、公共/媒体原件复用、重复查询、失败清理、asset 偏移，以及原件读授权到期只撤权不删文件。合成媒体记录和授权已精确清理。

## 真机48验收通过

2026-10-29，USB连接同一vivo，实际安装版本1.0.48（57）：

- 从独立测试工具经系统拖放把合成PNG放进生产暂存坞，再拖给另一UID的路径型接收器。目标实际取得授权并读取成功，不是仅收到drop回调。
- 用户打开微信文件传输助手后，从生产暂存坞拖入同一合成图，微信实际显示了该图片。微信在松手后直接显示为聊天图片，没有确认预览；代理未点击发送。随后暂存数量归零。
- 用户另行确认窗口行为、投放及重启后位置记忆正常，并要求跳过这部分后续测试。

记录位于`artifacts/screenshots/phone48-usb-resumed/acceptance.json`，图片证据`wechat-inserted-synthetic.jpg`只保留合成测试图区域。没有使用用户原图作为投放素材。
