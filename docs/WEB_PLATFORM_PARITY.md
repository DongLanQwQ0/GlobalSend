# Web 与 App 的交互一致性

## 共用行为，平台能力分开接入

- 设备发现、分组、文本版本、文件清单、去重回执和路径检测沿用同一协议。
- 点击设备直接发送；多设备先进入多选，确认发送后退出多选。
- 接收、历史、文件页沿用相同的多选、拖动、删除和返回语义。
- 文件操作优先排列打开、保存到本机、加入待发送，删除与详情置后。Web 不显示无法调用的系统定位功能。

## 浏览器拖放适配

`web/src/drop.ts` 负责浏览器格式识别、投放时读取文本和遮罩状态；`folder.ts` 负责原始 File 与目录树。页面只负责把读取到的内容加入待发送。

- 外部文件和文字可投到整个窗口，文件保持原始字节；链接不再因缺少 text/plain 被丢弃。
- 只认当前网页自己发起的拖动。其他窗口的 GlobalSend 标记、丢失 dragend 后留下的节点，都不能拦住新的外部投放。
- 在 drop 事件内获取 File、目录入口与字符串回调；异步处理时不再读取已关闭的拖放数据仓库。
- 原生拖拽跨过子元素的 dragleave 不立即关闭遮罩；真正离开后关闭，投放、取消和切到后台立即关闭。页面刷新渲染期间保留遮罩状态。
- 浏览器的文件、剪贴板、通知和全屏由 Web API 接入；Windows Shell 和 Android 系统拖放继续由各自平台代码接入。

## 本轮证据

`web/tool/accept_window_drop.mjs` 使用已有固定浏览器配置，通过 Chromium 的可信拖放事件连续投放真实磁盘文件、纯文本、链接及 HTML 文本，并检查子元素穿越和页面重绘时的遮罩稳定性。Windows GlobalSend 的实际 OLE 手势仍需人工端到端验收。

## 地址显示修正

Dart 主动连接的 Socket.address 不能当作真实本机源地址。直连探测优先采用已经校验过的对端返回的 TCP 来源地址（对端观测，可能经过 NAT）；旧对端可使用已明确绑定的源地址。系统选路且没有观测值时显示未获取，不合成虚假的源地址箭头。此变更只调整诊断取值，不改变候选路径和连接回落顺序。
