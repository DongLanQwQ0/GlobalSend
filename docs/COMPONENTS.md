# 组件与状态命名

| 名称 | 含义 |
| --- | --- |
| 待发送区 / 待发送卡片 | 已确认、可发送及整卡拖放的本地内容 |
| 建议卡片 | 尚未确认的剪贴板或媒体，不参加普通发送及全部拖动 |
| 设备区 / 设备卡片 | 指定投递目标；拖入只高亮这一张设备卡 |
| 组内共享区 / 共享文本框 | 实时共同编辑，不触发收件强调 |
| 文件复制引用卡 | 指定来源公开的远端文件引用；拉取后关联真实本地副本 |
| 自动剪贴板槽位 | 接收端全局一个，最新内容覆盖旧内容；不产生普通收件或历史 |
| 接收区 / 已发送 / 文件库 | 正式收件、发送历史、本机文件的三个页面 |
| 接收坞 | Windows 独立接收窗口；Android 悬浮接收与暂存窗口 |
| 接收页 / 暂存页 | 接收坞内的两种内容视图；接收记录与用户暂存分开 |
| 收件强调页 | 普通主动收件的大预览/网格；手动拉取和自动剪贴板不弹此页 |
| 按需拖放 | 未下载的远端引用先拖至目标，目标请求真实数据时拉取并交付 |

## 文件复制引用的生命周期

未拉取 → 拉取中 → 本地可用。拉取中不重复请求；本地可用后打开、复制或拖动已有副本，不再次下载。外部原件消失时才重新呈现可拉取状态。手动拉取不触发收件强调页。关联以引用/请求/传输标识为准，不用名称猜测身份。

## 已确认的自动剪贴板槽位

整个接收端只保留一个槽位，不按来源设备增加槽位。新内容覆盖旧内容；指定目标投递，不广播。静默更新，不唤起、不新弹接收窗口、不自动展开接收坞。已显示的界面立即刷新。

Android 坞的接收页、Windows 接收窗口有内容时排第一位；其余平台在固定位置展示同一状态。文字复制与拖放保留；图片写入只在Windows、iPad和允许的桌面Web/iPad浏览器中提供，Android与iPhone不写图片，图片槽位仍可预览、拖放和加入待发送。不写普通接收、已发送或文件库记录；用户主动加入待发送或暂存后才转成普通内容。

每次用户提出新要求，先整理理解、说明作用域与状态，再实施；不要把“建议”“引用”“本地文件”混称为“剪贴板推送”。
