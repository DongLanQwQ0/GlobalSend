# 组件与状态命名

| 名称 | 含义 |
| --- | --- |
| 待发送区 / 待发送卡片 | 已确认、可发送及整卡拖放的本地内容 |
| 建议卡片 | 尚未确认的剪贴板或媒体，不参加普通发送及全部拖动 |
| 设备区 / 设备卡片 | 指定投递目标；拖入只高亮这一张设备卡 |
| 组内共享区 / 共享文本框 | 实时共同编辑，不触发收件强调 |
| 文件复制引用卡 | 指定来源公开的远端文件引用；拉取后关联真实本地副本 |
| 自动剪贴板槽位 | 接收端全局一个，最新内容覆盖旧内容；不产生普通收件或历史 |
| 接收区 / 已发送 / 文件库 | 正式收件、发送历史、本机文件的三个页面 |
| 接收坞 | Windows 独立接收窗口；Android 悬浮接收与暂存窗口 |
| 接收页 / 暂存页 | 接收坞内的两种内容视图；接收记录与用户暂存分开 |
| 收件强调页 | 普通主动收件的大预览/网格；手动拉取和自动剪贴板不弹此页 |
| 按需拖放 | 未下载的远端引用先拖至目标，目标请求真实数据时拉取并交付 |

## 接收坞悬停发送

Windows接收坞和Android悬浮坞：外部拖入悬停1秒进入设备目标，移出后1秒恢复普通内容。未满1秒就移出会取消进入；恢复倒计时中返回会取消恢复，保持设备模式；恢复后仍可再次悬停1秒进入，允许同一次拖动反复进出。离开立即停止边缘滚动并取消设备高亮，悬停本身不发送。Android原有“拖出本坞内容即显示设备”保留，恢复视图不销毁仍在进行的拖动或源卡片；拖动结束或坞关闭会清理等待任务。

## Windows 文本拖出

文本拖放同时提供原文字和 TXT 虚拟文件。文件名取文本首个非空行，最多12个字符，清理Windows不允许的文件名字符；没有可用标题时叫`文本.txt`。例如`明天下午三点开会.txt`；本次运行中再次导出同一标题时使用`明天下午三点开会 (2).txt`、`(3)`，不加产品名或时间串。同一次拖动中反复查询文件名保持不变。拖到桌面或资源管理器文件夹时，系统创建 UTF-8（含 BOM）的 TXT；拖到接受文字的编辑器或本应用待发送区时仍可直接插入文字。鼠标、触屏、主窗口和接收坞共用原生数据对象，不创建额外历史或临时导出文件；取消拖放不留下 TXT。目标已有同名文件（例如以前运行导出的文件）仍由系统处理，不擅自覆盖。

## 文件复制引用的生命周期

未拉取 → 拉取中 → 本地可用。拉取中不重复请求；本地可用后打开、复制或拖动已有副本，不再次下载。外部原件消失时才重新呈现可拉取状态。手动拉取不触发收件强调页。关联以引用/请求/传输标识为准，不用名称猜测身份。

## 已确认的自动剪贴板槽位

整个接收端只保留一个槽位，不按来源设备增加槽位。新内容覆盖旧内容；指定目标投递，不广播。静默更新，不唤起、不新弹接收窗口、不自动展开接收坞。已显示的界面立即刷新。

Android 坞的接收页、Windows 接收窗口有内容时排第一位；其余平台在固定位置展示同一状态。文字复制与拖放保留；图片写入只在Windows、iPad和允许的桌面Web/iPad浏览器中提供，Android与iPhone不写图片，图片槽位仍可预览、拖放和加入待发送。不写普通接收、已发送或文件库记录；用户主动加入待发送或暂存后才转成普通内容。

每次用户提出新要求，先整理理解、说明作用域与状态，再实施；不要把“建议”“引用”“本地文件”混称为“剪贴板推送”。

## 设备排序

设备区、选择设备列表以及接收坞的目标设备按本机发送使用次数降序排列。以唯一设备ID记账，多组同一设备只显示一次；同名不同ID各自统计，改名不丢次数。次数相同时保留原列表顺序。在线/离线30秒保留规则不变，不因常用就复活过期设备。

从117版起累计：中心接受的普通文本发送或文件批次各计一次，以原事件/传输ID去重，刷新、失败请求与同ID重试不增加次数。自动剪贴板同步及远程引用的被动拉取不影响排序；点击设备、拖到设备、分享直发、文件库转发和坞内投递沿用相同发送入口。统计独立保存在本机，不写进文件历史，因此删除历史或切组不清空常用顺序。
