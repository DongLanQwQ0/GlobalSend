# Android 快速选路

刷新并行测试网卡和蜂窝候选，发送优先复用有效成功记录。范围顺序是 **局域网 → 公网 → 中继**；手动指定的范围失败时不暗中改路。

## 并行检测，不逐个等待

- `candidate_routes.dart` 组合本地接口和对方候选。排除地址族不匹配、回环、链路本地及明确无 Internet 能力的 IMS 接口；校园私网前缀不同不等于不可达。
- 普通接口进行绑定源地址的 HTTPS `/probe`；蜂窝候选由 `NetworkBridge.probePeer` 取得有 Internet 能力的 Android Network，只绑定本次连接，不修改系统或整个进程的默认网络。
- `RouteProbes`、反向 HTTPS 与 RTC 预检可并行进行。原生探测使用空闲后回收的可复用线程池，不排在两个阻塞请求后面。文件传输使用独立执行器，文件并发默认四个。
- 刷新先重新上传本机地址，再读取所有已加入组的去重设备并集；网络、证书、候选变化使旧测量失效。启动、恢复和获得焦点也推动刷新。

## 复用与失败回落

已测成功记录保存源地址/网卡或蜂窝方式。同一范围内按延迟排序，持平时优先非蜂窝；关闭蜂窝后不使用蜂窝记录。前向 HTTPS、反向 HTTPS、RTC 的有效成功结果接入同一个选择器，不让一个未测形式挡住其它已就绪形式。

未知候选的只读检测和选择共用约一秒预算。已证实路径的新建文件连接则保留完整握手窗口：`clamp(4×RTT+100 ms, 1000 ms, 3000 ms)`。这修复了检测成功后，授权/TLS/响应头却被 209–389 ms 小切片截断而误回落中继的问题。

某个已测地址失败，只剔除该地址对，继续该范围内其它已测路径。旧连接/写入器关闭后再切换，避免覆盖同一半文件；文件流连上后不受连接计时器截断。蜂窝唤醒和真实跨网握手仍可能超过一秒，不能用凑时间的方式提前判定直连失败。

中心支持 `relayStreaming` 时，中继读取已提交块，上传和下载重叠；不是先上传整份再下载。中继仍排最后，超过 32 MiB 保留确认。

## 证据与当前交付

- `NativePeerProbeSchedulingTest` 验证两个阻塞探测不阻止第三个可达请求开始。
- 原生真实 TLS 回归覆盖 700 ms 响应头等待、首个已测地址超时后使用第二个已测地址，以及建立流之后的长时传输；见 `artifacts/logs/multi-group-native-tests.log`。
- 中心真实 HTTP 和原生接收器验证上传未完成时已得到中继字节，末字节等待校验；见 `server-live-relay-regression46-final.log` 和 `native-live-relay46-final.log`。
- 早期三个同机 Web RTC 客户端曾在 694 ms 内完成三对 nonce/echo；这是浏览器生命周期证据，不是校园网、手机蜂窝或 iPad 公网延迟。
- 当前Windows和手机为54+64本地候选，后续边缘滚动平滑修订尚待手机覆盖；中心/Web沿用已上线选路与流式中继能力。54没有修改选路算法，也没有新增真实跨网验收证据。具体安装状态见 `PROGRESS.md`。
