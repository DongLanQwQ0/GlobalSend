# 自动剪贴板同步

## 一个静默更新的槽位（112）

Windows在设置中打开“同步剪贴板”并选择目标设备，后续新复制的文字和截图自动发送给该设备，不加入或清空待发送草稿。文件/文件夹由独立的“文件复制推送”控制，仅发布指定设备可拉取的引用。

Windows同步的开启状态和目标设备按中心配置保存。重启及重新连接后恢复；目标暂时离线不清空配置。关闭后仍记住目标，但目标下拉框禁用，已有目标离线时也可重新开启并等待连接。旧版只保存在内存，首次升级后需开启并选择一次，此后重启无需重复操作。

所有接收端使用独立的“接收剪贴板同步”开关，默认开启。整个客户端只保留一个自动剪贴板槽位，最新内容覆盖旧内容，不按来源叠加。关闭该开关后不更新槽位或系统剪贴板，也不改成普通收件。

槽位不写接收、已发送或文件库记录，不唤起应用、不弹收件强调页、不新弹接收窗口、不自动展开接收坞。已显示的工作区和接收坞静默刷新；Android接收页和Windows接收窗口中排第一位。接收同步不授予移动端后台读取剪贴板的权限。

图片写入的新平台策略：Windows与iPad保留自动及手动图片复制，Android和iPhone取消图片写入；相应图片卡片不再显示复制按钮。文本复制不变，图片仍可接收、预览、建议、拖放、加入待发送或暂存。移动Web按宿主系统执行同样策略，桌面Web和iPad浏览器仍需系统允许写入。iPhone/iPad共用IPA，通过运行时设备类型区分，不按整个iOS包统一关闭。

用户主动点击“加入待发送”或“暂存”后，才转为普通内容。私有槽位图片被替换后释放；正在显示、系统剪贴板或拖放提供方仍在使用时保留到使用结束，不删除普通收件原件或已加入待发送的副本。

## 与建议、文件复制推送的区别

- 剪贴板建议是待确认内容，点击才加入待发，也可以直接长按拖动；不自动随普通发送，也不代表已经发给其它设备。
- 自动同步监听版本和格式，只向选定目标自动投递文字或截图；接收端用一个静默槽位呈现，不进入普通收件。
- 文件复制推送只公布指定目标可拉取的引用，点击后才传原文件或目录，不把文件自动写进目标系统剪贴板。

当前自动文本同步仍会跳过空文本、超过8192个UTF-8字节的文本，以及匹配私钥、password/secret/token、验证码等关键词的文本；带本应用来源标记的内容不再次转发，以免回环。剪贴板事件合并等待至少350毫秒，距上次发送不足一秒时等到该间隔结束。以上是现存逻辑，不应描述为所有复制内容都会无条件同步。

## 图片复用传输通道，不生成普通历史

来源监听系统剪贴板版本与格式。PNG、DIB、DIBV5、Bitmap截图在后台读取成应用自有PNG/BMP源文件，绑定该次系统版本；读取前已被替换则放弃旧快照。通过原有SHA校验、去重、暂停/取消、断点与内网→公网→中继选路传输，继续遵守中继32MiB确认设置。中心只增加一个图片剪贴板标记，不增加二进制接口或第二套数据通道。

`POST /transfers`可传可选的`clipboard:true`，仅用于单张图片；普通请求不变。中心将来源设备ID和传输ID写入返回的`transfer.clipboard`，重试、查询和重启后保持一致；设备访问仍限于已有传输双方。能力标记是`info.features.clipboardImages`，旧中心需升级后才能自动同步图片。

Windows接收端通过系统WIC在工作线程生成PNG、DIB、DIBV5格式，再写入剪贴板。来源标记避免双向回环。新复制替换尚未完成的同步快照，较新的远程内容不会被较晚完成的旧图片覆盖；关闭同步或改目标会取消尚未完成的图片写入。正常状态不增加说明，失败才在设置中显示状态。
