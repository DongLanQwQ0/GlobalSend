# 多组连接

## 使用

- 在 **设置 → 分组 → 加入分组** 输入另一组的密码；可填写一个便于识别的名称。
- 各组的在线设备合并显示。相同 `deviceId` 只出现一次；同名的不同设备仍分别显示。
- 发送时直接选择设备，不必先切换组。存在任意共同组即可互传，地址交换和连通检测也使用这份设备并集。
- 组内共享框的下拉菜单只切换共享文本，各组文档、草稿和修订独立。切换不会重新登录、停止传输或清空本地文件及历史。
- 设置中的退出图标只退出对应组；“断开服务器”仍是本地断开整台中心。

## 实现

一台已注册客户端仍只有一个设备 ID、一个令牌和一个文件历史库。`device_groups` 存放设备与组的多对多关系，旧设备自动迁入其原来的组。加入更多组不会再调用设备注册接口。

中心使用 `SELECT DISTINCT` 合并共同组的设备，存在共同组才允许新建发送、交换地址和发起检测。设备名称不作为身份依据。组内共享通过 `groupId` 显式指定文档，WebSocket 更新携带同一个组 ID。

### 协议

- `GET /api/v1/groups`：本设备的组列表。
- `POST /api/v1/groups/join`：`{groupKey, name?}`，加入或创建组；重复加入不产生新成员记录。
- `DELETE /api/v1/groups/:groupId`：退出指定组，不删除本地文件与历史。
- `GET/PUT /api/v1/group/shared-text?groupId=...`：选定组的共享文本。
- `POST /api/v1/groups/key?groupId=...`：更换选定组的密码。
- `GET /api/v1/devices`：返回去重设备列表和本设备的组列表。

新中心通过 `features.multiGroup` 宣告能力。单组旧客户端及不带 `groupId` 的共享请求继续使用其原始组。旧中心不显示新增的多组控件。

## 验证

- 中心真实请求：多组交集去重、同名设备不误合并、非首组文本和文件发送、组文档隔离、退出、重启保留原身份和成员关系。
- Flutter 真实中心 GET/PUT/WebSocket：加入额外组不换令牌、不清待发送；不同组共享文本互不覆盖；退出组仍保留身份。
- Web 控制器：身份、文件引用、历史存储键保留；组文档分离；不调用重新注册。
- Flutter 934×611、390×844 实际渲染：共享组选择器、分组设置和加入弹窗无布局溢出，使用矢量/绘制控件，不新增字体。
