# 重复文件不再传输

接收端已保存同一内容时，再次发送只刷新接收时间、排序和自动清理期限，继续使用原文件。文件名不参与内容匹配；同名但内容不同的文件仍正常接收。

## 工作流程

1. 发送方发出文件摘要和大小，不先上传文件。
2. 接收方在接受传输前查找本地已保存文件，并验证当前文件的大小和 SHA-256。
3. 命中后，以 `POST /transfers/:transferId/files/:fileId/reuse` 提交 `{sha256,size}`。中心返回 `received`、`reused:true` 和 `receivedAt`，通知发送方完成；没有文件上传、下载或新副本。
4. 接收方更新同一物理文件的接收时间和清理期限。旧传输记录过期、切换组密码或服务器，不影响仍保存在本地的文件参与匹配。

删除、修改或当前无法读取的文件不算命中。每台接收设备独立确认自己的本地副本，不能仅凭发送方历史跳过传输。

## 当前覆盖

- Windows、Android 原生客户端，以及具有持久本地文件副本的 Web 客户端。
- Web 仅通过浏览器“下载”且未保留可访问副本时，应用无法确认下载目录里的文件仍存在，不会误报已保存。
- 中心和 Web 已部署整目录复用；当前已安装的 Windows／Android 1.0.23+32 仍按独立文件复用，文件夹按真实目录结构传输。原生整目录复用源码已就绪，尚未更新安装包。
- 自定义旧中心未提供 `features.fileReuse` 时，客户端保留原传输流程。

## 整目录复用

中心和 Web 已上线；原生接收端源码已实现，手机按当前要求保留现有包。

1. 中心提供 `features.folderReuse` 后，接收端在接受之前匹配一个完整、已登记的接收根目录。
2. 枚举实际目录，核对全部相对路径、文件／目录类型、空目录和文件内容。根目录显示名可以不同，但不能把不同旧目录的散落文件拼成一个新目录。
3. 全部一致时调用 `POST /transfers/:transferId/folders/:rootId/reuse`，提交每个成员的 `{fileId,sha256,size}`。中心一次确认该根目录的全部成员，使用同一接收时间，其他根目录不受影响。
4. 接收端保留原路径、文件字节、登记身份和清理归属，批量刷新时间。没有创建第二个根目录，没有重新上传或下载文件。

有内容变化、增删空目录、额外文件、读取授权不可用、仅选中部分成员，或旧中心不支持该接口时，继续正常传输。回执丢失可从已持久化的原目录引用恢复；某个成员已开始传输时不切换为目录复用。

Web 在原目录元数据旁保留每次传输的持久别名，文件库只显示一套原件。重启后仍能读取、展开转发；更换接收目录时迁移原件，别名继续指向迁移后的原目录。通过别名删除时仍只删除已登记的接收内容，保留用户后来放入目录的其他文件。

验证：真实中心、生产 Web 控制器和磁盘目录完成 74 个成员的首次传输、断点恢复与重复发送；重复发送全成员同一回执、offset 为零、原件修改时间不变、没有第二个根目录。实际 Edge 使用既有固定配置，生产 worker 在真实 OPFS 中完成匹配、重启恢复、展开转发和删除。日志位于 `artifacts/tmp/web-folder-reuse-final-20261028.log`，浏览器证据位于 `artifacts/tmp/web-folder-browser-1793166128481/result.json`。

## 协议与保留行为

`/reuse` 仅由本次接收方调用，在 `offered` 或尚未开始载荷的 `accepted` 阶段确认。重复提交返回同一次回执，晚到的 `accept` 不会把它变回传输中。`transport:direct` 沿用无中继载荷的终态兼容表示；`reused:true` 区分本地复用和实际直连。

中心只保存回执，不要求旧传输 ID 或保留旧文件字节。现有中继、断点续传、暂停和取消流程不变。
