# 重复文件不再传输

接收端已保存同一内容时，再次发送只刷新接收时间、排序和自动清理期限，继续使用原文件。文件名不参与内容匹配；同名但内容不同的文件仍正常接收。

## 工作流程

1. 发送方发出文件摘要和大小，不先上传文件。
2. 接收方在接受传输前查找本地已保存文件，并验证当前文件的大小和 SHA-256。
3. 命中后，以 `POST /transfers/:transferId/files/:fileId/reuse` 提交 `{sha256,size}`。中心返回 `received`、`reused:true` 和 `receivedAt`，通知发送方完成；没有文件上传、下载或新副本。
4. 接收方更新同一物理文件的接收时间和清理期限。旧传输记录过期、切换组密码或服务器，不影响仍保存在本地的文件参与匹配。

删除、修改或当前无法读取的文件不算命中。每台接收设备独立确认自己的本地副本，不能仅凭发送方历史跳过传输。

## 当前覆盖

- Windows、Android 原生客户端，以及具有持久本地文件副本的 Web 客户端。
- Web 仅通过浏览器“下载”且未保留可访问副本时，应用无法确认下载目录里的文件仍存在，不会误报已保存。
- 当前按独立文件复用；文件夹仍按真实目录结构传输，不将旧目录中的单个文件引用拼接成不完整的新目录。
- 自定义旧中心未提供 `features.fileReuse` 时，客户端保留原传输流程。

## 协议与保留行为

`/reuse` 仅由本次接收方调用，在 `offered` 或尚未开始载荷的 `accepted` 阶段确认。重复提交返回同一次回执，晚到的 `accept` 不会把它变回传输中。`transport:direct` 沿用无中继载荷的终态兼容表示；`reused:true` 区分本地复用和实际直连。

中心只保存回执，不要求旧传输 ID 或保留旧文件字节。现有中继、断点续传、暂停和取消流程不变。
