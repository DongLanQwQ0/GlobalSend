# GlobalSend Web

轻量 Safari / 浏览器客户端，使用 Vite、TypeScript 与 DOM/CSS。API 类型来自 `packages/protocol`，端点以 `docs/API.md` 为准。

```sh
npm --logs-dir ./artifacts/logs/npm-web --prefix web ci
npm --logs-dir ./artifacts/logs/npm-web --prefix web run test
npm --logs-dir ./artifacts/logs/npm-web --prefix web run build
npm --logs-dir ./artifacts/logs/npm-web --prefix web run dev -- --port 5173
```

开发服务器将 `/api`（含 WebSocket）代理至 `http://127.0.0.1:8787`。启动中心后打开 `http://127.0.0.1:5173`。生产环境由中心同源提供 `web/dist` 到 `<base>/app/`，相对资源路径支持中心 URL 路径前缀。

## 构建、测试与下载的存放位置

以上命令从项目根目录运行。项目专用产物留在本项目中：

- `web/dist/`：生产构建。
- `web/node_modules/.vite/`、`web/node_modules/.vite-temp/`：Vite 项目缓存及配置加载临时文件。
- `artifacts/logs/npm-web/`：上述命令的 npm 日志；需要保存终端测试输出时也写入 `artifacts/logs/`。
- `artifacts/downloads/`：浏览器验收下载与比对文件。验收时指定此目录；工具若只能返回默认下载路径，立即移入这里，不将默认路径作为项目产物长期存放位置。

DOM/控制器测试使用 dev-only `linkedom` 和内存编译。目录集成测试在 `artifacts/tmp/web-folder-*` 内启动真实中心，并将生产接收 worker 的文件系统接口接到项目内真实磁盘；不使用系统 `tmpdir`，不读取用户浏览器或用户文件。测试输出保留在 `artifacts/logs/`。可复用工具链缓存放公共 F 盘。

## 连接和使用

1. 网页默认连接提供此页面的中心。输入至少 10 位组密码加入；设备名自动建议，也可在设置修改。默认记住设备，下次打开恢复连接。
2. 发送区添加文本、剪贴板、文件、媒体或文件夹。点击设备即发送并清空本次队列；发给多台时，先进入多选，再确认发送。手机使用发送、接收、已发送、文件库四个分页。
3. 默认自动接收同组内容。中继确认阈值默认 32 MiB，可在设置修改；含超限文件的整个批次留待手动确认，避免部分接受时误拒同批大文件。直连可用时按局域网、公网、中心中继顺序连接；浏览器的直连使用 RTC，不把中心在线当成两设备直连可达。
4. 文件按服务器 chunkSize 分块上传；最多并发两个文件。上传恢复依据中心已提交的偏移。发送源保留原 File 引用，不复制为安装包、缓存文件或 ZIP；刷新页面后，未完成的发送源仍需通过“继续”重新选择原文件核对。
5. 只读文本整面拖动，使用“复制”复制全文；实际编辑框保留输入、选字和 IME。多选后的卡片整面用于选择，可全选、复制文本或批量删除。
6. 普通中继文件的“下载”仍可交给系统浏览器；浏览器下载交接不等于已保存到系统 Files。RTC 接收文件和结构化文件夹流式保存到本机文件库，完成后才确认其文件已接收。
7. 切换组保留本地历史和文件库，停止旧会话的连接、摘要及传输。旧请求的延迟响应不会写回新会话；本地文件库不因换组而成为新的身份。

## 真正的文件夹传输

- 文件夹按真实目录和文件条目发送，保留原始根目录、嵌套路径与空目录；没有 ZIP 或扁平化回退。普通文件批次最多 32 项，结构化目录批次最多 10000 项。双方中心/客户端需支持 `folderTransfer`；不支持时明确要求更新接收端。
- 支持系统目录 picker 的浏览器直接枚举目录句柄，可选择完全空的文件夹；拖入目录同样保留空目录。只有 `webkitdirectory` 文件输入能力的平台会补齐文件的父目录，但该输入 API 本身不会提供没有文件的空目录。
- 目录条目创建后单独 `/received`，不发送伪造的零字节文件 payload。实际文件继续使用原有中继/RTC 字节流、偏移和完整性校验。
- 默认字节位置是 OPFS `globalsend-received-v1/<scope>/received/<根目录>/...`，不是一批编码文件名的 `.data` 文件。`.json` 仅记录接收状态、真实位置和根目录预留；不代替文件层级。
- 设置的“文件夹接收位置”可选 File System Access 目录。选择后直接流式写入该目录，不再保留第二份 OPFS payload。外部目录权限失效时要求重新授权，不静默换到其他位置。
- 不同传输的同名根目录使用 `名称 (1)` 等独立目录；同一传输刷新或重启复用已预留位置，并从已落盘的文件偏移继续。
- 文件库可查看目录内容、重新加入待发或转发，转发仍是原层级条目。重命名修改文件库中的逻辑名称，不复制或搬移已保存字节。
- 显式导出目录需要浏览器支持目录选择与写入；不支持时仍可在文件库保留、查看和转发，并明确提示不能导出目录，不偷偷生成 ZIP。目录的系统外拖同样受浏览器能力限制，应用内拖回待发不丢层级。
- 自动清理默认一天，可调整时长、类别和大小。只删除应用记录的接收条目，不递归删除整个用户目录；用户后来放入其中的文件保留。

### 紧凑界面与中继限额

- 登录页使用单表单：中心、设备名、组密钥、连接；高级方式折叠。工作区只保留设备、发送、接收坞与在线/设置，不再显示营销标语、常态安全段落或每项 24 小时脚注。
- 桌面保持发送/接收两栏；900 px 以下收起侧栏，目标选择仍在发送区；760 px 以下使用“接收 / 发送”导航，默认接收；同一页只显示当前区。支持说明使用正常字号与对比度，触控按钮最小 44 px。设置中分组管理与连接说明折叠。
- 按钮使用“复制 / 下载 / 重试 / 取消”。文件状态区分“等待接收 / 传输中 / 已就绪 / 对方已保存 / 已交给浏览器”；`received` 优先，不把中心已就绪当成对方落盘，也不把浏览器下载交接当成本地保存。
- Web 仅使用中继。默认自动接收上限 32 MiB / 文件；含超限文件的批次保留复选框和一键“接收”，不自动上传，也不因为接收同批小文件而拒绝大文件。设置可改上限。发送按钮旁显示数量、总大小与“中继”，点击一次即发送，无第二次流量确认。全部二进制尺寸统一使用 KiB / MiB / GiB。

### 文件选择器生命周期修复

主代理实际文件选择时观察到 `No node found for given backend id`：系统选择框仍打开时，HTTP/WS 刷新会重建 `#app`，原来放在工作区模板中的隐藏输入节点随之被移除。

`#file-input` 与 `#resume-file` 现固定放在 `web/index.html` 的 `#app` 外，工作区重绘不再替换它们。监听仅安装一次；打开时记录会话代次与续传目标，选择后清空 input value，支持再次选择同一文件。退出或切换中心会清理待选上下文，旧会话的延迟选择不进入新会话。续传摘要完成后使用原先捕获的目标 key，不读取后来被改变的选择目标。HTTP/WS 更新与普通渲染保持运行，没有通过暂停刷新掩盖问题。
