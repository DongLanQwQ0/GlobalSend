从“我要做什么”出发，重新理解 GlobalSend。这里展示现有能力、平台差异，以及可讨论的入口方案；布局建议尚未替换运行版本。

01 / MODULE ROLES

三个容器，三种使用场景

共享内容与状态，不复制整套界面。先确定每个模块要帮用户完成什么，再决定按钮放在哪里、占多大空间。

交接原则

主界面负责完整处理；Android 暂存坞服务跨应用中转；Windows 接收窗口服务后台到件。自动剪贴板保持静默，组内编辑不当作收件；iOS、iPadOS、Web不照搬Android悬浮窗。

02 / WORKSPACE

先看入口，后看选项

交互示意点击布局中的区域，查看功能、现有入口与建议入口。示意设备和文件不是实际数据。

05 / RECOMMENDATIONS

减少寻找，不削减能力

P0 优先澄清语义 · P1 再整理入口
设置的建议分组

日常动作不藏进设置。

设备相关开关可以就近配置，但仍操作同一份设置状态。

  1. 连接与设备服务器、分组、设备名、可达性
  2. 收发与后台同步、接收、路径、并发、通知、启动
  3. 存储接收位置、迁移、自动清理
  4. 外观与帮助主题、指南、更新、版本
06 / BEFORE WE REARRANGE

哪些已经有，哪些还要确认

入口重组前先保留这份边界。编译、定向检查、实际系统操作是不同证据；未验收不等于未实现。
