# GlobalSend

自托管的跨设备文本与文件接收坞。Windows / Android 使用 Flutter，iPad 使用 Safari；中心通过 Docker 部署。Web 自动连接本站，原生客户端可自定义中心。

## 开始使用

网页版：[GlobalSend](https://123.207.180.163/globalsend/app/)。Windows/Android 的中心地址为 `https://123.207.180.163/globalsend`。

## 收发工作区

- **外观**：设置中可切换亮色、暗色、中性灰，以及绿、蓝、紫、玫瑰、琥珀、石板六种主题色。即时生效、在本机记住，不随分组切换；图片保持原色。
- **收发工作区**：桌面左右双窗格，标题旁横排文本/剪贴板，右栏上方接收/已发送/文件库标签；移动端发送/接收双分页。默认点设备发送并清除成功批次，多选后确认。待发方卡与紧凑设备各自滚动；点待发空白输入文本，共享区保持可见。Windows默认950×650，左栏整体不滚动。
- **内容预览与拖放**：接收两列卡片展示图片缩略图、文本/HTML摘要、大小和时间，路由与位置进入详情。文件卡片整卡拖出；文本正文用于选择、复制，从标题或空白区域拖出。Windows整窗口拖入，使用灰色虚线“松手”遮罩；Android提供圆角拖出卡片图像。
- **网址**：消息、收件弹层和文本文件预览识别 `http://`、`https://`、`www.`。点击直接使用浏览器打开；复制保留全文，已发送文字仍可编辑。
- **文件夹与引用**：选择或拖入目录后打包为保留层级的 ZIP，接收 ZIP。原生普通发送文件仅保留外部引用，目录归档在相关传输结束后释放、历史引用原目录；删除发送历史不删除原件，原件消失后移除引用。Web仅在当前页持有外部 `File` 引用，刷新后不能恢复磁盘引用或持续检测源文件删除。
- **共享文本**：同组设备实时双向编辑，中文输入期间不打断；并发编辑保留草稿，可选择远端或保留本地。不通知、不唤起、不进入收件页面，与发送草稿和系统剪贴板独立。
- **轻量阅读器**：原生和 Web 都支持收到文字只读查看/复制、已发消息原位编辑；原生常见 UTF-8 / 带 BOM 的 UTF-16 文件可预览。
- **新内容与窗口**：单项大预览、多项网格，支持拖出、复制和Esc。接收多选支持整卡选择、全选/批删，右键与更多共用菜单。Windows记住窗口bounds，托盘卸载主界面而保留接收核心；有焦点在主窗接收，失焦使用独立右下接收坞，不改主窗口尺寸位置。坞可拖回待发，关闭后释放UI-only engine。
- **Android后台**：保留接收服务；API30+后台收件请求同一Activity的有界应用小窗，不依赖厂商freeform，失败才通知。小窗约半屏高、可移动/缩放、圆角，可手动展开全屏；文本通知支持复制。按用户选择不新增无障碍权限、不自动检测桌面切全屏；实际vivo后台稳定性与小窗操作待真机验收。
- **本地文件库**：两列显示本机全部已保存文件，离线、换中心或退出分组后仍可看，按时间、名称或大小排序；长按编辑，可重命名、删除或显式转发。刚掉线的设备在 30 秒内也可尝试发送。图片支持缩略图和缩放预览。
- **接收与清理**：在“设置 → 存储”选择 Windows 文件夹或 Android 系统目录，直接写入，不再保留第二份永久副本。默认保留 24 小时，可改小时/天，并按类别和大于/小于 MiB 筛选清理。清理会删除本应用接收的文件，包括自选目录内这些文件；不扫描目录中其他文件，不删除原发送文件或另行导出的副本。
- **连接**：原生周期检测地址；刷新、启动、恢复及获焦点重新发布自身IPv4/IPv6与RTC能力，中心通知同组。自动直连共用1秒总决策预算，候选并行探测，LAN→公网→中继；真取消失败尝试，已连传输不限1秒。保留手动选路、断点与大中继确认，不把尚未握手的能力标成已可达。

新版已构建，Windows隔离客户端真实收下PNG/HTML，Native实际渲染与Web独立浏览器交互已检查。手机后台/锁屏弹出、系统回收及实体触屏跨应用落下仍待实机确认。短步骤见 [实机测试](docs/QUICK_TEST.md)。

## 开发入口

iPad 未签名真机包通过 GitHub Actions 构建，下载后手动签名安装，见 [iPad 构建说明](docs/IPAD.md)。

原生版本构建、复制到`E:\Programs\GlobalSend`并重启、ADB推送/覆盖安装/启动统一使用`npm run release:local`；细节见[原生说明](client/README.md)。

需要 Node.js 24.19+（24.x）和 npm。各子项目有独立锁文件，根目录不使用 npm workspaces。

```sh
npm run setup
npm run build
npm test
npm run dev
```

`npm run dev` 同时启动中心与 Web 开发服务，Ctrl+C 关闭本次启动的两个进程树。在原生客户端填写中心地址及至少十位组密码，Web 使用页面所在中心；相同密码直接加入同组，其他组不可见。

组密码用于入组，已有设备凭据可直接恢复登录。新登记不再接受引导码或邀请码；旧设备无需重新配对，文件与历史保留。设备地址仅保存在中心进程内，不作为永久设备清单。

Flutter SDK 使用现有的 `E:\Programs\flutter`，Android SDK 为 `F:\Android\Sdk`。原生客户端的具体运行与构建说明见 `client/README.md`。

允许构建和运行后，`npm start` 使用已编译中心；`npm run client:windows` 启动已构建的 Windows Debug，`npm run client:windows -- --release` 明确选择 Release。启动器不自动构建，也不悄悄改用另一配置；当前运行的旧版窗口不会因源码变化自动升级。

根入口统一使用 `artifacts/local-center/` 保存本地中心数据，`artifacts/native-state/` 保存客户端状态与接收文件，临时文件留在 `artifacts/tmp/`。显式设置的部署目录仍优先，不改全局环境。直接在 `server/` 启动则沿用该模块的目录约定。

## 文件放置

项目专用测试数据、截图、日志、下载和临时文件统一放 `artifacts/`；构建产物保留在各模块的 `dist/` 或 `client/build/`。不要把本项目测试数据留在系统 Downloads 或用户 AppData。

工具链和可复用缓存使用公共位置，例如现有 `F:\Android\Sdk`、`F:\Android\GradleCache`；新的公共下载缓存优先放 F 盘，不复制或迁移已有工具链。

## 当前设计

- WS 只传文本、在线通知与协商，不承载大文件。
- 同组文件默认自动接收，保留手动确认、取消与重试；文本独立成条。直连不设流量上限；中继默认超过 32 MiB 需确认，阈值可在设置调整。
- 自定义中心配置按服务器实例隔离，不跨服务器复用设备凭据。
- 同中心退出后切换分组，也隔离设备、接收坞、游标与待发送任务；不持久化 group 密钥。
- 默认依次选择局域网、公网、中继，保留手动指定；手动失败不暗中改路。原生之间优先使用 HTTPS 拉取/反向推送，Web 互通使用 WebRTC。
- 原生大文件优先直传；超过 32 MiB 需中继时，默认先确认。蜂窝直传不设流量上限，开关按中心保存。
- 中心是受信任服务，可读取转发文本与中继文件。TLS 不等同于端到端加密。
- 移动端不承诺无限后台在线或后台读取剪贴板。
